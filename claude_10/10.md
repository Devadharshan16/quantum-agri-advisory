## A. PROJECT OVERVIEW

### 1. Problem and intended user

The project classifies agricultural conditions into one of 22 crop classes using seven soil and environmental measurements: nitrogen, phosphorus, potassium, temperature, humidity, soil pH, and rainfall. The intended user is a farmer or agricultural advisor who enters these conditions and receives a recommended crop. This is implemented in [predict.py](../predict.py), [app.py](../app.py), and [api.py](../api.py).

It is a classification system, not an agronomic optimization system: it does not optimize crop rotation, farm-level crop allocation, profit, irrigation scheduling, or expected yield.

### 3. Objective and research questions

**Objective:** Build a hybrid quantum-classical classifier that encodes seven crop-condition features with a quantum feature map, computes a quantum fidelity kernel, and uses a classical SVM to recommend one of 22 crops.

Formal research questions are **NOT FOUND IN REPO**. The stated research themes are:

1. Can QSVC avoid the optimization difficulties associated with the earlier VQC?
2. How does bandwidth gamma affect accuracy and kernel concentration?
3. How does QSVC compare with classical classifiers?
4. How robust is the approach to shot and depolarizing noise?
5. Can the pipeline provide reproducible crop recommendations?

### 5. Full pipeline

1. Download the CSV.
2. Treat the final column as the crop label.
3. Encode labels with `LabelEncoder`.
4. Perform an 80/20 stratified split.
5. Fit `StandardScaler` on training data only.
6. Fit `MinMaxScaler` on training data only to map values to `[0, pi]`.
7. Transform test data with those scalers and clip it to `[0, pi]`.
8. Multiply scaled values by `gamma`.
9. Encode rows into statevectors using `ZZFeatureMap`.
10. Compute `K(x,x') = |<phi(x)|phi(x')>|^2`.
11. Train `SVC(kernel="precomputed")`.
12. Select hyperparameters using training-only cross-validation.
13. Evaluate once on the held-out test set.
14. For inference, repeat preprocessing, compute a kernel vector against saved training states, and predict a crop.

## C. QUANTUM COMPONENT

### 8. Feature map

The selected production configuration is a `ZZFeatureMap` with:

| Parameter | Value | Source |
|---|---:|---|
| Qubits | 7 | [models/metrics.json](../models/metrics.json) |
| Repetitions | 3 | [models/config.json](../models/config.json) |
| Entanglement | Full | [models/config.json](../models/config.json) |
| Quantum trainable parameters | 0 | [models/metrics.json](../models/metrics.json) |

Each of the seven features controls phases on one qubit. ZZ interactions encode pairwise feature relationships. A row `x` becomes a state `|phi(x)>`; two rows are compared by the similarity of their states.

### 9. Quantum kernel

[qkernel.py](../qkernel.py) assigns each row to the feature map, simulates the resulting statevector with Qiskit `Statevector`, stores one statevector per row, and computes:

```text
K[i,j] = |<psi_i | psi_j>|^2
```

The main experiment is:

- exact statevector simulation;
- noiseless;
- not shot-based;
- not executed on quantum hardware;
- numerically equivalent to noiseless fidelity evaluation.

Declared versions in [requirements.txt](../requirements.txt) and saved metadata:

| Package | Version |
|---|---:|
| Qiskit | 1.1.0 |
| Qiskit Machine Learning | 0.7.2 |
| Qiskit Algorithms | 0.3.0 |
| Qiskit Aer | 0.14.2 |
| scikit-learn | 1.4.2 |
| NumPy | 1.26.4 |

The code calls this a “Swap test,” but it does not build an explicit ancilla-based Swap Test circuit; it directly computes statevector overlap.

### 10. Gamma

`gamma` is a scalar applied before encoding:

```python
states = compute_states(feature_map, X * gamma)
```

It controls how strongly differences in scaled features affect state similarity. The selected value is `gamma=0.1`, from [models/config.json](../models/config.json).

### 11. Trainable quantum parameters

The selected model has **0 trainable quantum parameters**, according to [models/metrics.json](../models/metrics.json). The feature map is fixed; only the classical SVM is optimized. This avoids quantum gradient optimization and the VQC barren-plateau issue.

## D. CLASSICAL COMPONENT

### 13. SVM settings

The production classifier is `sklearn.svm.SVC(kernel="precomputed", C=10.0)`, using the quantum fidelity kernel. `SVC` uses one-vs-one internally for multiclass classification. The earlier [train.py](../train.py) uses `C=1.0`, so it is a legacy path, not the selected v2 configuration.

### 14. Classical baselines

[baselines.py](../baselines.py) evaluates:

- RBF-SVM: `C` in `[0.1, 1, 10, 100, 1000]`; gamma in `[1e-4, 1e-3, 1e-2, 1e-1, 1, scale]`.
- Linear SVM: `C` in `[0.01, 0.1, 1, 10, 100]`.
- Random Forest: `n_estimators` in `[100, 300, 500]`; `max_depth` in `[None, 10, 20, 30]`.
- k-NN: neighbors in `[3, 5, 7, 11, 15]`.

All use repeated stratified 5-fold CV with 3 repeats and seed 42. The comparison uses the same intended split and preprocessed features, but the quantum and classical search spaces and procedures are not identical. It is a performance comparison, not proof of equal computational budget.

### 16. Why V1 was slow

For 1,760 training and 440 test samples, V1's loops imply:

- Training kernel: `1,760 × 1,760 = 3,097,600` pair evaluations.
- Test kernel: `440 × 1,760 = 774,400` pair evaluations.
- Total: `3,872,000` pair evaluations.

The training kernel is symmetric, but V1 computes both `(i,j)` and `(j,i)`. The exact number of internal circuits executed per pair by Qiskit is **NOT FOUND IN REPO**. V2 instead computes one statevector per sample and uses matrix multiplication.

## G. LIMITATIONS & HONESTY CHECK

### 26. Limitations

1. Main results use noiseless exact statevector simulation.
2. No real quantum hardware run is configured.
3. Dataset is static; no live weather or soil API is used.
4. Upstream dataset licensing/page is not verified in the repository.
5. Main result uses one 80/20 split with seed 42.
6. There are only 20 test samples per class.
7. Gamma search may not establish a global optimum outside the tested grid.
8. Baseline and QSVC search procedures are not identical.
9. Random Forest is slightly more accurate than QSVC.
10. McNemar's test does not show a significant difference.
11. Runtime outputs are not saved as structured benchmark results.
12. Final circuit depth and gate count are not saved.
13. Raw CSV and prepared `data/` arrays are not tracked.
14. Required inference `.joblib` artifacts are ignored/not present in the tracked file list.
15. Missing-value and anomaly handling are not implemented.
16. Noise-study outputs are not present.
17. The dataset may be relatively easy; classical models are near-perfect.
18. `frontend/` and `web/` are starter applications, not connected deployments.

### 27. Unsupported and supported claims

Do not claim quantum advantage, greater speed, hardware validation, live-weather validation, guaranteed best crop, geographic generalization, or crop-allocation optimization. The project does support claims that a 7-qubit quantum-kernel classifier is implemented, uses exact fidelity statevectors, has zero trainable quantum parameters, reaches 99.091% test accuracy and 0.9909 macro-F1 on 440 test samples, and is statistically indistinguishable from the best classical comparison under the saved McNemar test.

### 28. Bugs, inconsistencies, and metadata issues

- “Swap test” is used as a label, but no explicit ancilla Swap Test circuit is executed.
- [09_vishal_firstreport.md](../09_vishal_firstreport.md) contains stale 4-qubit, PCA, 550-sample, and 60.23% claims that conflict with the v2 artifacts.
- `train.py`, `trainv1.py`, and `trainv2.py` are different training paths and can produce inconsistent artifacts.
- [baselines.py](../baselines.py) expects `test_f1_macro` in `models/metrics.json`, but the v2 file does not contain it; QSVC macro-F1 is blank in the baseline CSV.
- Inference softmax scores are not calibrated probabilities, as noted in [predict.py](../predict.py).
- The API does not apply the CLI's explicit feature-range validation.
- API CORS is configured as `allow_origins=["*"]`.
- Circuit depth and gate counts are printed but not persisted.
- “No barren plateaus” means no quantum parameter optimization is used; it is not an empirical proof that all barren plateaus were ruled out.

### 36. Three-sentence summary

This project builds a hybrid quantum-classical crop classifier using seven soil and environmental features from a balanced 2,200-row dataset. It encodes rows with a seven-qubit `ZZFeatureMap`, computes an exact statevector fidelity kernel, and trains a classical SVM, reaching 99.091% test accuracy and approximately 0.9909 macro-F1 on 440 test samples. The result demonstrates a working quantum-kernel pipeline, but Random Forest is slightly better and the statistical test does not support a quantum-advantage claim.
